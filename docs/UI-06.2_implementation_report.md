## 1. Executive Summary

Phase UI-06.2 is a precision corrective pass targeting two key surfaces:
1. **Telemetry Balance (Problem A):** Resolving the visual leftward skew and premature termination of the rightmost metric (Humidity), achieving true edge-to-edge balance across 4 mathematically equal columns (25% each) when AQI is absent and 5 equal columns (20% each) when AQI is present.

## 2. Telemetry Layout Correction & Edge-to-Edge Balance

### 2.1 Problem Analysis
In `WeatherTelemetry.tsx`, although the CSS grid previously specified `sm:grid-cols-4`, internal metric blocks were styled with `justify-start` and variable left-padding (`pl-0 sm:pl-3 lg:pl-4`). Because the Humidity block content (Icon + "Humidity" + "82%" + "Humid") spans ~90px within a ~250px column, it hugged the left divider, leaving the remaining ~160px on the right empty. This created the optical illusion that the telemetry strip terminated prematurely with an unfinished void on the right.

### 2.2 Corrective Architectural Solution
1. **Centered Column Placement:**
   - Each column now uses `flex items-center justify-start sm:justify-center min-w-0 w-full px-2 sm:px-3 lg:px-4 py-1 sm:py-0`.
   - The inner metric grouping (`flex items-center gap-2.5 sm:gap-3 min-w-0`) is centered within its allocated 25% column.
   - The distance from the container's left edge to the Temperature metric exactly matches the distance from the Humidity metric to the container's right edge.
2. **Harmonized Metric Anatomy:**
   - **Badges:** All icons are housed in an identical 36×36px rounded badge (`w-9 h-9 rounded-xl flex items-center justify-center flex-shrink-0`), with standardized 16×16px icons (`w-4 h-4`).
   - **Label Row:** Uniform uppercase tracking label: `Temp`, `Rain`, `Wind`, `Humidity`, and `Air Quality`.
   - **Value Baseline:** Uniform font sizing and baseline alignment (`font-tabular text-base sm:text-lg font-medium leading-tight`).
   - **Secondary Meta:** Consistent description styling (`type-meta text-[11px] truncate mt-0.5`).
3. **Column Boundaries & Dividers:**
   - Vertical dividers (`sm:divide-x sm:divide-[var(--border-subtle)]`) represent the exact column boundaries at 25%, 50%, and 75% across the entire width.

## 4. Forecast Data Resolution Discovered

Inspection of the backend weather pipeline (`backend/app/services/weather_service.py` lines 120–131) and schemas confirmed:
- Open-Meteo is queried with:
  ```python
  params = {
      "latitude": latitude,
      "longitude": longitude,
      "current": "temperature_2m,relative_humidity_2m,apparent_temperature,precipitation,weather_code,wind_speed_10m",
      "hourly": "temperature_2m,apparent_temperature,relative_humidity_2m,precipitation_probability,precipitation,weather_code,wind_speed_10m",
      "forecast_days": 7,
      "timezone": "auto",
  }
  ```
- **Authoritative Resolution:** The underlying data layer delivers strictly **hourly** forecast data (24 data points for a 24-hour window).
- **Sub-hour / Minute Data:** No minute-level or 15-minute precipitation feed (`minutely_15`) is currently enabled or returned in the payload.

## 5. What Was Intentionally NOT Fabricated

In accordance with strict product integrity principles:
- **No Fabricated 5-Minute Points:** We do NOT synthesize or invent artificial 5-minute weather values. When a user scrubs between 1:00 PM and 2:00 PM, the timeline resolves truthfully to the nearest actual meteorological observation (1:00 PM or 2:00 PM).
- **Visual Smoothing vs Data Interpolation:** The Catmull-Rom cubic spline path is used exclusively for visual rendering of the temperature line and area gradient. The inspection engine never samples intermediate curve heights as fake weather predictions; all telemetry, tooltips, and badges reflect actual hourly observations.
- **Deferred Minute-Level Precipitation:** Near-term minute-by-minute precipitation requires future backend provider support (e.g., Open-Meteo `minutely_15` or radar nowcasting APIs). This capability is documented as deferred to a dedicated data-layer phase.

## 6. Forecast Interaction Architecture & Continuous Hit Surface

### 6.1 Continuous Interaction Overlay
- Replaced segmented point `<rect>` elements with a unified, transparent full-width interaction overlay:
  ```tsx
  <rect
    x={0}
    y={0}
    width={W}
    height={totalH}
    fill="transparent"
    style={{ cursor: 'crosshair', touchAction: 'none' }}
  />
  ```
- Captures all pointer interactions across the entire width (`x = 0` to `x = 640`), ensuring zero dead zones between major labels or curve segments.

### 6.2 Nearest-Point Selection Algorithm
- Exported and unit-tested pure resolution function:
  ```typescript
  export function findNearestForecastIndex(
    svgX: number,
    points: Array<{ x: number; idx: number }>
  ): number
  ```
- Evaluates `Math.abs(p.x - svgX)` across all 24 available hourly forecast points.
- Guarantees that hovering anywhere along the timeline immediately snaps to the nearest actual hourly point.

## 7. Axis Representation & Intermediate Points

### 7.1 Visual Communication of Intermediate Resolution
- The time axis now renders discrete intermediate tick marks across the baseline for **every single available hour**:
  - Major ticks (3-hour intervals: 12 PM, 3 PM, 6 PM, 9 PM): height 6px, stroke opacity 0.8.
  - Minor ticks (intermediate hours: 1 PM, 2 PM, 4 PM, 5 PM...): height 3px, stroke opacity 0.45.
- Visually communicates that every hour is an interactive data point without cluttering the axis with 24 text strings.

### 7.2 Dynamic Inspected Hour Axis Badge
- When an hour is inspected (e.g. 1:00 PM / 13:00):
  - An active inspection badge (`rect` + monospace text) renders directly at `active.x` on the time axis:
    `[ 1 PM ]`
  - Nearby static 3-hour orientation labels are intelligently hidden if within 18px to prevent visual collision.
  - As the user scrubs across the timeline, the badge glides smoothly along the axis, giving immediate feedback of the exact hour under inspection.

## 8. Selected Point Visualization & Scrubber Guide

When an hour is selected:
1. **Vertical Inspection Guide:** A dashed vertical guide line extends from above the curve down through the precipitation bar track to the time axis.
2. **Point Halo:** A double-ring halo (`r=7` fillOpacity 0.25, `r=4.5` solid center) highlights the exact point on the temperature curve.
3. **Active Temperature:** The temperature numeral is displayed in bold accent color directly above the point.
4. **Active Condition Icon:** The WMO weather icon is rendered cleanly above the temperature numeral.
5. **Precipitation Bar Highlight:** The corresponding hourly precipitation bar is rendered at full 100% opacity with an accent border.

## 9. NOW Marker Independence

- The `NOW` marker is permanently anchored at `currentIdx` (the actual current hour in the local timezone).
- When a user scrubs to any future or past hour (e.g. 6:00 PM), the `NOW` vertical guide and label remain fixed at the current hour.
- Inspection and current observation remain distinct concepts.

## 10. Touch & Keyboard Scrubbing

### 10.1 Touch Scrubbing (Mobile)
- Continuous touch-drag tracking via `onTouchStart` and `onTouchMove`.
- `touchAction: 'none'` on the SVG prevents viewport scroll conflicts during timeline scrubbing.
- 2.5-second inactivity timeout on `onTouchEnd` allows the user to inspect the state comfortably before smoothly reverting to current observation.

### 10.2 Keyboard Scrubbing (Desktop & Accessibility)
- **ArrowRight:** Steps to the next available hourly data point (`selectedIdx + 1`).
- **ArrowLeft:** Steps to the previous available hourly data point (`selectedIdx - 1`).
- **Home:** Jumps directly to the initial hour (index 0).
- **End:** Jumps directly to the final hour (index 23).
- **Escape:** Resets inspection back to current observation.

## 11. Tooltip & Telemetry Synchronization

- **Tooltip Positioning:** Floating card dynamically toggles between left and right sides (`style={{ [tooltipLeft ? 'right' : 'left']: '12px' }}`) based on cursor position relative to chart center, guaranteeing zero occlusion of the active point and no container overflow.
- **Parent Surface Synchronization:** `onInspectHour` notifies `WeatherAnswerSurface.tsx`, which updates `WeatherTelemetry.tsx` with:
  `Previewing Forecast: 1:00 PM`
  and displays that hour's exact temperature, feels-like, rain probability, and wind velocity.
- Clicking `"Back to Current"` instantly clears the inspection state.
